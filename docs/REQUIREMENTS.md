# Требования к проекту

Здесь все требования владельца проекта: каждое замечание и правило, которое он дал. Документ дописывается, старые строки не удаляются. Статусы — на 7 ноября 2026, проверены в коде, в базе или в браузере.

Статусы: **Сделано** — проверено; **Частично** — часть сделана; **Не сделано**; **Решение владельца** — ждёт ответа; **Правило** — постоянное требование, соблюдается в каждой правке.

## 1. Построение страниц и тексты

| № | Требование | Статус | Как проверено |
|---|---|---|---|
| 1.1 | Все страницы строятся с языками и текстами, которые хранятся в базе данных. Структура страницы (HTML и компоненты) не меняется от языка и текста | Частично | Главная строится так; справка и остальные страницы ещё не перенесены |
| 1.2 | Все тексты сайта хранятся в базе: интерфейс, справка и любые другие | Частично | В базе тексты главной и общей оболочки; справка не перенесена |
| 1.3 | Каждая строка текста привязана к адресу страницы и языку. Адрес `_common` — тексты, общие для всех страниц | Сделано | Таблица `page_texts` (`src/db/schema.ts`), загрузчик `src/lib/texts.ts` |
| 1.4 | Тексты раскладывает по HTML браузерный скрипт по `id` (`data-text="id"`). Элементы в HTML пустые, текст приходит из базы через `/api/texts` | Сделано | Браузер: все элементы главной заполнены текстами из базы (`src/components/site/TextBinder.tsx`) |
| 1.5 | Перевод на новый язык и правка текста — без изменения кода страницы, только строки в базе | Частично | Для добавления языка код всё ещё меняется: тип `Locale` и переключатель языка |
| 1.6 | Заголовок и описание страницы (title, description) берутся из той же базы на сервере, потому что поисковики и превью ссылок не выполняют скрипт | Решение владельца | Сделано так; если нужно строго только скриптом, переделать |
| 1.7 | JSON-файлы в `src/content/` — только исходник для загрузки в базу (`npm run db:seed-texts`), в работе сайта не читаются | Сделано | `scripts/seed-texts.ts` |

## 4. Интерфейс

| № | Требование | Статус | Как проверено |
|---|---|---|---|
| 4.1 | Визуальная система берётся из старого проекта: синий акцент, светло-серый фон, белые панели, системный шрифт, моно-подпись, карточки-«листы» на титульной странице | Частично | Тёмная тема проверена в браузере; светлая тема и мобильная ширина не проверены |
| 4.2 | Тёмная и светлая тема выбираются по системной настройке, как в старом проекте | Частично | Тёмная проверена; светлая только токенами |
| 4.3 | На каждой странице одна `h1`, ссылка «Перейти к содержанию», подписанная навигация | Сделано | HTML главной: один `h1`, skip-ссылка в `SiteFrame` |
| 4.4 | Кнопки и текст на телефоне умещаются без горизонтальной прокрутки | Не сделано | Не проверено |
| 4.5 | Выбор языка как в старом проекте: кнопка с флагом и кодом открывает список языков с поиском. Сверху готовые языки (есть тексты в базе), ниже — «перевод скоро», недоступны. Список языков — из `src/lib/ui-languages.ts` | Сделано | Браузер: список открыт, поиск и группы на месте, выбор «Русский» переводит страницу и тексты |
| 4.6 | Язык, которого нет в базе, нельзя выбрать. Перевод через ИИ при выборе (как в старом проекте) пока не сделан | Решение владельца | Сейчас такие языки недоступны; нужно решить, делать ли ИИ-перевод при выборе |
| 4.7 | Инструменты (логотип, язык, кнопки, поиск и др.) — отдельные компоненты. Панели (шапка, левая, правая) — контейнеры, куда страница вставляет инструменты. Состав зависит от страницы и от состояния клиента; инструменты могут появляться и исчезать во время работы | Не сделано | Не начато; нужно определить, какие состояния клиента есть |
| 4.8 | Размер и вид символов ‹ и › (сворачивание панелей) задаёт сам пользователь в своих настройках. По умолчанию — как в старом проекте (`.rail-toggle`: 0.75rem × 1.4rem, шрифт 1.05rem, цвет вторичного текста) | Частично | Размер по умолчанию как в старом проекте; пользовательской настройки пока нет |
| 4.9 | Наведение на ‹ или › выдвигает панель поверх текста, уход мыши прячет её; клик закрепляет (как `RailCollapse.tsx` в старом проекте) | Не сделано | Сейчас клик только скрывает панель |
| 4.10 | Свёрнутое состояние панелей запоминается в cookie и применяется на сервере при загрузке страницы (как `RAILS_COOKIE` в старом проекте) | Не сделано | Сейчас состояние сбрасывается при перезагрузке |
| 4.11 | Узкий экран: боковых панелей нет, оглавление открывается по ☰ снизу и закрывается по выбору главы или Esc | Не сделано | Сейчас на узком экране панели просто скрыты |
| 4.12 | Аватар в шапке — синяя заливка; активный значок (например 💬 у открытого обсуждения) подсвечен фоном, как `.header-icon-btn.active` | Не сделано | Сейчас аватар и активный значок без подсветки |
| 4.13 | Полное совпадение стилей шапки и панелей со старым проектом: поиск, рамки, типографика, отступы, состояния при наведении | Частично | Перенесены размеры шапки, значков, переключателей и отступов; остальное не сверено |

## 5. Правила разработки

| № | Требование | Статус | Как проверено |
|---|---|---|---|
| 5.1 | Текст в компонентах не вписывать строками. Только `data-text` / `data-text-aria` | Правило | Соблюдается |
| 5.2 | Старый проект не меняем. Исправления — только в новом | Правило | Соблюдается |
| 5.3 | Новые функции не должны ломать порядок страницы: страница — структура, тексты — данные | Правило | Соблюдается |
| 5.4 | Окно — один объект. Его состояние (открыты ли панели, какой вид показан в каждой) общее. Инструменты меняют состояние, содержимое панелей выбирается по нему. Окна не живут отдельно друг от друга | Правило | Сделано: `PanelProvider` (`PanelState.tsx`), виды панелей в `BookTemplate.tsx`, действия инструментов в `exampleTools.ts` |
| 5.5 | Куки и мобильный режим (4.10, 4.11) и остальные элементы старого проекта (4.9, 4.12, 4.13) — позже, после структуры | Решение владельца | Отложено по решению владельца |
| 5.6 | Все рабочие окна строятся по одному шаблону из шести элементов: три зоны шапки (слева, по центру, справа) и три колонки под ней (левая панель, содержимое, правая панель). Элементы и инструменты сайта открываются и размещаются внутри этих шести элементов. Наверху — меню и значки, по настройкам пользователя; в колонках — то, что пользователь выбрал для работы | Правило | Каркас готов: `SiteFrame`, `SiteHeader`, `PanelState`, `BookTemplate` |
| 5.7 | Все параметры окна хранятся в настройках пользователя: ширины колонок, свёрнутость, открытый вид панели, размер символов и т. п. | Не сделано | Решение владельца: хранить во внутреннем состоянии клиента (мгновенный отклик) и в базе данных (источник истины). Cookie не использовать: они утяжеляют каждый запрос к серверу |
| 5.8 | Логин — инструмент. Он показывается в зависимости от страницы и состояния сайта, а не всегда | Правило | Не сделано в коде |
| 5.9 | Язык интерфейса сейчас хранится в cookie `ui-language`. Нужно решить, перевести ли его в то же хранилище, что и настройки окна | Решение владельца | Вопрос открыт |
| 5.10 | Три вида объектов. Шаблон — то, что должно быть на странице (сетка). Поведенческие — показывает система по правилам, клиент не решает. Пользовательские — клиент сам включает и выключает в настройках | Правило | Не сделано в коде |
| 5.11 | Правила показа поведенческих объектов. Кнопка управления конфигурацией страницы — видна всегда, когда клиент залогинен. Кнопка логина — видна, пока клиент не залогинен, на всех страницах кроме титульной. После логина она скрыта, а инструменты пользователя видны | Правило | Не сделано. Аккаунтов в проекте пока нет, поэтому все клиенты считаются незалогиненными |
| 5.12 | Объектная модель. Один объект окна (шаблон) на всех страницах. Постоянные объекты одинаковы везде: переключатель проекта, поиск, библиотека, кабинет, язык, уведомления, аватар, группа 💬 🎧 🤖. Страница добавляет только свои инструменты и своё содержимое. Эталон — `components/site-template/SiteTemplate.tsx` и `/dev/template` в предыдущем дизайне (`AiTextCore`) | Правило | Не сделано в новом проекте: сейчас шаблон книги отдельный и не содержит постоянных объектов |
| 5.13 | Что открывается в колонках шапки и панелях — зависит от выбранных инструментов и их переменных. Инструмент получает переменные (например, какой вид открыть), а содержимое панелей вычисляется из них | Правило | Частично: виды панелей выбираются инструментами, переменных и постоянных объектов пока нет |
| 5.14 | Реализация объектной модели: переменные окна (`src/components/shell/WindowStore.tsx`) — панели, поиск и инструменты обмениваются ими по ключам. Состояние сохраняется в браузере (localStorage). Постоянные инструменты окна (`src/components/site/CoreTools.tsx`) одинаковы на всех рабочих страницах; титульная страница их не получает | Частично | Проверено в браузере: 💬 🎧 🤖 переключают вид правой панели, поиск сохраняется после перезагрузки. Не сделано: хранение в базе данных по пользователю; проект, уведомления и аватар пока без действий; настройки инструментов (5.7) |
| 5.15 | У каждой страницы есть дефолтный набор инструментов и их мест. Пользователь убирает и возвращает инструменты (например, поиск) в настройках (⚙, вид правой панели). Выбор хранится по адресу страницы и не влияет на другие | Частично | Проверено в браузере: поиск на `/library` убирается галочкой, после перезагрузки остаётся скрытым, галочка возвращает его. Не сделано: хранение в базе; добавление из каталога инструментов, которых нет на странице по умолчанию; короткое мелькание скрытых инструментов до загрузки настроек |
| 5.16 | Страницы без окна — не отдельные страницы, а инструменты. Вход и регистрация — поведенческий инструмент (показ по состоянию клиента, см. 5.8 и 5.11). Урок, презентация, печать и слайды — инструменты, которые открываются в рабочем окне (в основной области или в панели). Адрес страницы может остаться ссылкой, которая открывает окно с нужным инструментом | Решение владельца | Не сделано в коде. Инвентаризация: `docs/TOOLS_INVENTORY.md` |
| 5.17 | Полный список инструментов сайта. У каждого инструмента есть дефолтное включение и дефолтное место. Пользователь может: поставить инструмент в любое место экрана (другая сторона, шапка, панель), скрыть его совсем, поставить на страницу, которую дефолт не предусматривает. Есть кнопка сброса к дефолту | Правило | Метаданные есть (`src/tools/<id>/index.ts`, реестр `src/tools/index.ts`). Выбор пользователя и сброс не сделаны |
