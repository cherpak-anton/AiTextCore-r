# Контекст: что такое старый проект и с чем работать новому

Для тех, кто (или что) будет писать новый проект. Читать первым.

## Что такое старый проект

**AiTextCore** — платформа для книг, которые читают, смотрят и слушают: ИИ объясняет непонятное, адаптирует текст под язык читателя, оживляет иллюстрации, проводит урок по главе. Книга — не только текст: к абзацам привязаны картинки, видео и аудио, а ИИ, перевод и голос работают по описанию автора.

Старый проект — рабочий сайт, накопленный за несколько месяцев. Он работает, но его структура выросла без общей архитектуры: компоненты, стили и поведение панелей повторяются на каждой странице, а шапка и боковые панели собираются вручную.

Где он лежит:
- git-репозиторий `AiTextCore`, тег **`legacy-2026-11`** — точное состояние до рефакторинга. Ветка `refactor/objects`.
- локальная копия для сравнения: `AiTextCore-legacy/` (git worktree из тега), запускается на порту 3001.

## Что в старом проекте (для ориентира)

- **Стек:** Next.js 16 (App Router), React 19, TypeScript, Drizzle ORM, PostgreSQL, S3-совместимое хранилище (MinIO локально), ИИ через API провайдеров и встроенный ИИ браузера.
- **Страницы:** книга (чтение, редактирование, оглавление, обсуждение, перевод, меню книги), кабинет (полки и книги), библиотека, приветствие, справка, настройки, администрирование платформы, читалка по ссылке.
- **Важные модули:** права доступа (`lib/authz.ts`), адаптация и перевод (`lib/adaptation.ts`), учёт потребления (`lib/usage.ts`), языки интерфейса (`lib/ui-strings.ts`), панели сайта (`components/AppShell.tsx`, `components/RailCollapse.tsx`).
- **Документы в старом репозитории:** `docs/ARCHITECTURE.md`, `docs/BOOK_FORMAT.md`, `docs/PERMISSIONS.md`, `docs/CONCEPT.md`, `docs/MANUAL.md` (руководство для пользователей), `docs/SITE_TEMPLATE.md` (черновик общего шаблона).

## С чем работать новому проекту

Новый проект — **рефакторинг на объектной структуре**, не переписывание с нуля по-другому. Поведение сохраняется, меняется устройство кода.

**Что сохраняем как есть:**
1. Стек: Next.js, React, TypeScript, PostgreSQL, Drizzle, S3-хранилище. Vue не нужен: весь интерфейс на React.
2. Модель данных: шкафы → полки → книги → главы → блоки; комментарии и реакции — те же блоки с привязкой. Схема базы берётся из старого проекта, миграции новые.
3. Правила приватности и доступа: e-mail никому не показывать; книга видна только по правам из `authz`; заморозка не распространяется на администратора платформы.
4. ИИ: адаптация и перевод — **только через ИИ самого пользователя** (его ключ или встроенный ИИ браузера). Платформа за чужой счёт ИИ не вызывает.
5. Языки интерфейса и переводы: язык интерфейса — по выбору пользователя, непереведённые книги помечаются на обложке.

**Что меняем (цель рефакторинга):**
1. **Объектный шаблон страниц.** Один общий объект сайта: верхнее меню и две боковые панели есть на каждой странице. Страница заполняет его своими инструментами и содержимым, а не собирает панели сама. Черновик описан в `docs/SITE_TEMPLATE.md` старого репозитория.
2. **Верхнее меню** — объект `TopMenu`: постоянные элементы (переключатель проекта, поиск, панели, язык, аватар) и инструменты страницы, которые задаёт каждая страница.
3. **Боковые панели** — один компонент `SidePanel` (левая и правая, у каждой свои инструменты сверху).
4. **Интерфейс на Material UI** (уже в зависимостях, `@mui/material`). Старые стили перенести по компонентам, не переписывать все разом.
5. **Разделение данных и вида:** загрузка данных — отдельно от компонентов; компоненты получают готовые объекты.

## Как переносить

1. Одна страница за раз, начиная с шаблона и книги как самого сложного образца.
2. Каждая перенесённая страница сверяется со старой (порт 3001) по списку действий.
3. Старый код не меняем: исправления делаем только в новом проекте.
4. Удалять старое нельзя, пока все страницы не перенесены и не проверены. Старое всегда доступно через тег `legacy-2026-11`.
